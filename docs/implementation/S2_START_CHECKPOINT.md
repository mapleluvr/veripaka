## 2. 环境与调用政策

Node **24.15.0**；Pi **0.99.1**；Python **3.12.7**；Pillow **10.4.0**。S1 的 Pi 0.86.1 和 `:high` 历史记录不改写。

共 **7 次真实 Pi 模型会话**：三次图像通路检查、三个候选方法会话、一次安装后冷复用。全部请求唯一指定的 `:max` 模型，关闭 extensions/session；没有换模型。响应 metadata 的实际别名为 `deepseek-v4.1-flash`，不等于请求换模。各次均没有记录到 provider 错误或超时，因此本轮没有触发传输重试；会话内的脚本错误、探索与修改保留在原始事件中。

`PI_OFFLINE=1` 只关闭 Pi 启动时的网络更新，不关闭实际模型调用。图像 pilot 预先登记了仅针对明确上游访问故障的有界重试政策，见归档的 `work/CAPABILITY_PROTOCOL.md`；没有把不可见图像或错误判断当作网络故障重跑。

## 3. 图像直读：三种输入均未建立可用性

| 条件 | 实际观察 | 结论范围 |
|---|---|---|
| `read` 两张 PNG | 工具返回 image/png 附件；模型报告 Invalid image format，不提供图形/验证码答案 | 此次 PNG 工具通路未通过 |
| `read` 等价 JPEG | 工具返回 image/jpeg 附件；仍无法识别 | 不能仅归因于 PNG 编码 |
| 初始消息直接附 PNG | 无工具调用；仍报告无像素 | 不能仅归因于工具结果这一入口 |

父 Agent 直接查看了图片；本地图像库可以解码。provider 本地声明含 `image`，但声明不是能力验收。这里没有捕获上游实际入站请求，**未定位错误究竟发生在哪个上游/适配层，也不推断该模型在所有环境都不支持视觉**。

这只阻止当前路线假定模型能直接做开放式视觉判断，不阻止采用有明确参考和判据的非模型图像检查器。

## 4. 真实浏览器控制：DOM 绿不等于画面正确

父 Agent 用现有 `playwright-core` **1.58.2** 驱动 Chrome **153.0.8010.53**，访问本轮启动的随机回环端口 HTTP 页面。该 Playwright 来自本机已有 openclaw 依赖，**不是已加入 Veripaka 的交付依赖**。

正常页和白色遮挡页中，按钮的 DOM `visible`、边界框与点击后的 `Saved` 均正常，但后一张真实截图没有按钮画面。父 Agent 查看了两张图，再以 Pillow 计算 `[44,108,244,156]` 区域：9,600 像素中 **9,491** 个不同，自比较为 **0**。

这确认了一个观察层差异，未证明自主方法发现，也不是一般视觉 oracle。记录含 HTTP identity、浏览器版本、URL、截图、根 PID 退出及服务器关闭；未完成所有浏览器子进程枚举或 guided owner/取消验收。生成程序以执行记录的事后导出形式留存，不冒充事前冻结的生产证据链。

## 5. 候选方法与反例：不凭自报成功晋级

这些任务只要求对已提供截图形成可复用的精确像素比较方法，没有要求验收整个网页。方法作者看不到评估者的 private 目录；实际工具记录未发现对该目录的访问。父 Agent 同时是内容作者、对象作者与评估者，不能据此宣称广域独立评估。

### R0：原 Skill，自动选择入口

模型确认 Pillow 可用后仍写了 **801 行**标准库 PNG 解码器，进行了多次自检；26 次工具调用、约 172 秒仅是本次记录，不是效益统计。

父 Agent 冻结候选后另行执行：

- 事前登记的重压缩同像素图片：0 差异；单像素改动：1 差异，符合预期。
- 事后挑战：只破坏 IHDR CRC，独立 Pillow 无法读取，但候选仍输出 `PIXELS_IDENTICAL` / exit 0；CRC 警告和交叉解码失败没有改变结论。

该候选不纳入正式 Recipe。反例转为策略校准材料，不能再用作修订后方法的独立留出证据。

### R1：新条件指导，但未消费正文

安装了新增指导的包，保持公开任务原文不变。实际工具记录没有读取 Skill 正文或 `strategy-discovery.md`；再次构造了自行解码的方法。**内容存在于安装包里，不等于进入了决策过程，不能归因于新指导。**

本轮评估准备另有父 Agent 流程失败：把 585 色图片量化到 256 色，错误地预期像素完全不变。断言失败，但组合 shell 没有 fail-fast，模型仍启动。该会话保留为探索材料，**不计作事前登记的留出评估**；没有事后补写登记时间。

### R2：显式 Skill 入口，仍不宣称知识产生收益

查证 Pi 文档后，任务显式使用 `/skill:veripaka`。原始用户事件包含展开的 Skill 正文；引用的策略文件仍未被读取。模型这次选择 Pillow，形成 **264 行**比较脚本，不再自建 PNG 解码器；但调用方式也变了、每条件只有一次会话，不能据此宣称策略造成效率或质量提升。

新的检查材料在模型启动前登记并冻结；准备时的异常类型误判被 fail-fast 阻止，没有多启动模型。候选冻结后的结果：

| 材料 | 结果 | 解释 |
|---|---|---|
| 同像素、不透明 RGBA 表示 | identical / exit 0 | 这个表示变化下比较成立 |
| 不同尺寸 | incomparable / exit 2 | 保守拒绝，不是假通过；也未给出差异结论 |
| 缺失 IEND | identical / exit 0 | 没有满足登记的严格容器完整性要求 |

最后一项必须分层解释：Pillow `load()` 可得到完整像素，而 `verify()` 拒绝截断容器。因此它限制候选进入要求完整参考文件的验证链，**不等于证明较窄的“已解码样本相同”结论错误**。不能把评估者增加的完整性要求不加说明地当成原任务要求。

另外，模型删除了自己的控制图片；声称 `interlace=True` 保存验证了交错输入。同环境复现所得 PNG 的 IHDR interlace 字节是 **0**，不能支持 Adam7 覆盖。这说明自报测试名称也必须核对实际材料。

R2 保留为有局部用途的研究候选，未进入正式 Recipe、未升级成熟度。没有继续重跑直到所有指标变绿。
