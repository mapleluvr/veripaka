## 父 Agent 的反思与修正

1. **只是换阶段名称，仍先接工具，会不会继续偏离产品？**
   已把 S2 的第一项交付改成从目标与真实对象形成可执行方法；工具/采集/调查支持是这条路径的依赖，不是独立产品成绩。也保留已有方法充分时的直接应用路径，避免为了展示能动性强迫每次重造测试。

2. **策略知识会不会又变成一套厚重结构？**
   首轮用入口 Skill 的少量参考正文和项目 Recipe，暂不建设策略 schema、registry、通用规划器。S2-4 明确允许删除没有实际增量的内容；不通过新增字段掩盖任务失败。

3. **独立验收是否会被自己写的样例骗过？**
   已要求预先登记正常/相关故障/误导观察/不足判定情形，方法确定后再应用留出变体。被评估的方法生成会话不得获得隐藏预期；评估者与方法会话分离，检查实际工具记录。仍有父 Agent 同时设计任务与通用指导而产生偏差的风险，不能因此宣称跨领域有效；后续需要独立任务/用户材料。

4. **新的主线会不会悄悄删掉原 S2 的安全边界？**
   原采集关联、旧服务/新源码、参考独立生命周期、调查完成、取消/清理约束被保留在 S2 的必需回归中。它们不再占据全部阶段问题，但失败仍不能闭合阶段。

5. **指定模型和工具是否真能支持视觉目标？**
   尚未实测，不预设可用。路线明确先核验图像消费能力；直接读图不可用时，需要实际支持同一主张的图像检查器，否则阻塞。不能用 DOM 或文件存在性替代图像结论。

6. **对照会不会只比较文本长度或 CLI 特有产物？**
   S2 固定底层能力，只试探候选策略正文的作用；S4 分探索/复用任务线，C/D 共享内容、底层工具和目标事实，由外部共同判据评价实际行为，不按 D 独有的格式评分。记录正文、运行和人工开销，保留负面与未完成样本。

7. **路线是否能直接开工，又没有偷跑？**
   S2 第一项是确定一个可重置真实对象、目标/公开资料与独立判定，不等待全知识库。实现前先经过 reviewer；目前只改设计/索引/使用说明，没有修改 src、tests、skills 或执行 E2E。
