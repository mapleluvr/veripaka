## 1. 推进原则与本轮变化

**以方法探索、条件化迁移和实际价值为主线，不再以接通工具或凑齐领域入口为主线。** Agent 应能从任务与真实对象出发，选择观察和干预、建立判据、产出有检出力的方法，而不要求用户预先设计每一步。

保留四个阶段和每阶段四个端到端问题，不增加 M0、通用本体、独立策略 registry 或架构自证关卡。TypeScript/Node、单 npm 包、文件存储、现有 Recipe/Plan 分工仍是工程默认。方法正文、真实对象、执行能力和校准试验在同一纵向任务中迭代，不先写完一座知识库再试用。

| 原路线的安排 | 本轮调整 | 保留的约束 |
|---|---|---|
| S2 以一条 guided/视觉链路接通为中心 | 改为首次自主方法形成；工具接入服务于真实观察选择 | 调查不冒充通过，对象/调用关联、参考生命周期、资源清理仍须正确 |
| S3 以三个默认入口及管理闭环为中心 | 改为跨条件迁移、误用识别与反馈改进；入口按实测方法整理 | 资格不自动晋级，迁移重绑定，材料不能依赖原机临时目录 |
| S4 主要比较方法文档与 CLI | 分开考察首次探索与后续复用，再归因知识内容和执行结构 | 独立判定、同条件对照、全成本和负面样本仍保留 |

S1 范围与四项原验收保持不变。未来 S2—S4 的编号按**本修订**解释；P001 原文及 S1 记录里对旧路线的描述保留为历史，不用于覆盖这里的新安排。

实现步骤可以依据阻塞调整，但不能通过删掉用户目标、降低 required 或隐去失败来缩小承诺。阶段记录区分已实现能力、方法有效性和产品收益；后两项不能仅由代码测试或 CLI 状态证明。

## 2. 总览与当前能力

```text
S1 执行与冷复用基础（已闭合，原验收不变）
  → S2 真实对象上的方法探索闭环
  → S3 条件化迁移与方法改进
  → S4 探索 / 复用价值归因与扩展决策
```

| 阶段 | 可交付的结果 | 不以什么作为完成标准 |
|---|---|---|
| S1 | 可安装、可冷复用的本地 command 验证基础 | 广域方法发现、完整前端能力 |
| S2 | 一个 Agent 从目标形成、实际执行并挑战测试方法的可复现样例；所需最小 guided/调查支持 | 截图存在、工具接通、漂亮的策略说明或无限新增字段 |
| S3 | 方法在新会话/新条件下可正确复用、调整或拒绝，并从反馈中改进 | 多拷贝几份 Recipe、改路径、凑齐三个 Profile |
| S4 | 关于探索质量、人工劳动、复用成本及 CLI 增量的可复核取舍 | 预设产品有用，或预设必须继续扩张 |

当前代码只支持 S1：local checkout + command + verification + executable Node 顶层命名测试。guided、investigation、广域策略检索等不能因本次规划而被声明已支持。不承诺未经测量的工期或收益百分比。

## 3. S1：可安装的最小复用闭环

当前状态：已闭合（内部 alpha）。四项实测、安装包身份、冷会话及已知限制见 [验收记录](implementation/S1_EVIDENCE_CHECKPOINT.md)。两条方法仍保留 trial 状态，阶段通过不自动改变方法成熟度。

### 目标

让 Veripaka 第一次成为可安装使用的产品，而不是文件格式演示：**一个 Profile、两条 Recipe、一种项目 command binding、一种真实报告适配，通过 pi 消费后在冷会话再次使用。**

### 实现范围

默认选一个 backend 参考项目，使用其现有测试框架；两条方法围绕“接口契约与边界”“写入后的读取一致性”。它们通过真实应用入口检查行为，共用一个已启用的命名测试命令，不为各方法建设不同执行器。若没有可直接复用的项目，用小型真实 HTTP 服务作为参考对象，不用只返回固定 PASS 的伪 runner 充数。

直接建设下列纵向链路：

```text
最简 init / recipe new
  → 编写 RECIPE.md 和项目绑定
  → lint / find / show
  → apply（含问题映射与快照）
  → run（受管 command + collect + finalize）
  → 结构化结果与简短反馈
  → 新 pi 会话检索并重用
```

必要实现：

- 建立单包、版本化 JSON 输出、文件资产布局与包内 launcher。一个入口 Skill 即可包含应用/编写提示；按需加载 Recipe。
- 支持一种明确的 checkout 关联方式：测试命令实际运行声明源状态，并能关联其启动的被测服务。不要首先尝试认证任意已有 localhost 服务或远程部署。
- apply 固定 required checks、judge、输入和来源要求；runner 适配将真实测试结果映射到检查，不只看 exit code。首版仅 command + verification 形成完成态；其他组合保留可读定义并返回明确 unsupported/host_required，不假装执行。
- 实现独立 run 产物、同项目互斥、最小异常恢复与 Windows 进程树取消；超时、缺材料或不支持的报告不能回落到上次成功记录。默认无自动重试。

最简创建入口只写必要文件，不做自动发现、导入升级或交互 wizard。结果可直接由 run 输出，独立 report/export 命令暂缓。方法格式允许在这两条实际路径中一次性修正，不另设格式审议阶段。

### 晋级验证：四项

| ID | 唯一要回答的问题 | 代表性验证与留下的证据 |
|---|---|---|
| S1-1 | 安装后的产品能否在冷会话真正复用方法？ | 用实际打包安装的 pi Skill/launcher 完成一次方法应用；关闭会话，新会话无需用户重讲方法主体即可找到并运行。保留输入、调用和结果。 |
| S1-2 | 两条方法是否测到了各自声明的行为？ | 对两条方法分别使用正常对象和破坏相关真实行为的对象，确认预期 check 能区分；保留对应 run，不能只修改脚本退出码。 |
| S1-3 | 结果是否依赖本次完整且有效的执行证据？ | 删除一个必需检查结果或替入旧 run 的报告时不能通过；正常路径可以通过。保留同一小型回归的预期与实测结果。 |
| S1-4 | 一次运行是否真正拥有自己的产物和进程生命周期？ | 在 Windows 启动一个带子进程的长任务，再发第二个同项目调用并取消前者；第二个明确 busy，前者的退出/清理状态与实际子进程一致，不出现串写或旧通过。 |

这些验证不等于全面证明方法有效或支持全部环境；它们足以判断最小链路是否成立。形状、零用例、skip、异常返回等程序回归随实现维护，不另设逐项晋级审批。

**阶段出口：** 内部 alpha，可在声明环境下积累 command 方法。此时不宣传完整 frontend/backend/debug-fix 默认套件，也不宣传弱模型成本收益。

## 4. S2：真实对象上的方法探索闭环

### 目标与第一条任务

让安装后的 Pi Agent 获得目标和真实项目，但**没有为该任务预写的完整 Recipe 或测试步骤**，能够认识对象、选择观察方式、形成可执行方法，实际检验并留下适用条件。只会提出建议、最后仍由用户设计所有步骤，不算完成。

第一条纵向任务以一个可重置的真实前端交互对象为主，包含视觉/结构问题和一个非视觉状态问题，使“截图”“DOM”“行为读取”都不是默认万能答案。优先采用用户提供或实际开发的对象；没有适合隔离的对象时，再建设带真实 HTTP/状态行为的小型参考项目，不用静态 PASS 页面充数。需求/可公开参考可以给出，不给隐藏故障位置、指定工具路线或完整目标方法。

首轮在执行前登记最小情形：正常对象、分别覆盖视觉与非视觉主张的相关故障变体、初始代理观察会误导的情形、无法充分判定的情形。可以共用一个小型项目，不要求为每项建新产品。登记公开目标、独立预期及允许的判断方式，不规定 Agent 必须采用的步骤。这里的“方法作者”指被评估的方法生成会话；评估者持有的隐藏材料不进入其输入，并检查实际工具记录确认未泄露。

每轮还须冻结公开提示、Skill/策略内容及评分口径的版本。父 Agent 同时承担内容作者和出题者的事实必须记录：任何用于修订内容的留出结果都转为校准材料，修订后的独立检查使用未参与修订的新留出材料；新开模型会话不能重置污染记录。“不适用”和“资料/能力不足而不可判定”分别登记。

### 单线实现顺序（不是新增阶段）

1. **固定任务边界与判定办法。** 确定用户目标、可重置环境、允许动作、公开资料和独立判定来源；区分探索校准样例与留出的正常/故障变体。先检查实际工具能力，不根据历史品牌印象规划适配。
2. **在真实任务上试写探索指导。** 扩展现有入口 Skill，按需加载少量条件化策略正文：观察层选择、独立状态读取、判据/停止边界。先让 Agent 形成实际观察与候选方法，再据消费失败修改文本；不预先建立七轴 schema 或填满通用领域库。
3. **补齐这条路径真正需要的运行能力。** 实现最小 `agent-guided` 与独立 `investigation` 分支、guide/next action、一次真实采集关联，以及该任务所需的参考接受与读取。可用一个浏览器链路同时提供结构和渲染，不要求接入三套工具。探索中改写测试的工作放在准备阶段；后续 verification 使用新冻结计划。
4. **完成方法与安装后对照。** 将生成的方法落到现有 Recipe/绑定并执行，关闭会话后复核其可消费性；用相同环境/工具/预算比较通用自测指导与附加候选策略正文的行为差异。不能只比较最后一段解释文字。

调查冻结的是范围、记录与停止协议，不是所有未来操作。固定协议可以容纳按观察选择下一步；调查完成不产生产品 verdict。已形成明确检查时另建 verification，避免用虚构 claims 给开放探索套壳。

### 必须保持的执行约束

这不是额外的产品卖点或新增阶段，但相关回归失败不能宣称 S2 闭合：

- guided 材料关联本次调用、产物和 endpoint；来源不足时不能获得 executable 资格，agent/human 判断保留性质。
- 原 URL 仍运行旧服务而源码已改时，不能声称当前 checkout 已验证；endpoint-observation 必须另立其范围，不能在失败后原地降级。
- 接受参考要有来源和理由，并脱离候选 run 的临时生命周期；后续失败不自动替换参考。
- 调查缺记录/崩溃不冒充完成；进程、产物、取消和锁沿用所有权规则。共享桌面无有效互斥时选隔离浏览器路径或报告阻塞。
- 新能力按用例增加契约与原生回归，现有 S1 command 路径、完整性检查和取消行为不得退化。尚未实现的组合继续明确 unsupported。

### 晋级验证：四项

| ID | 唯一要回答的问题 | 代表性验证与留下的证据 |
|---|---|---|
| S2-1 | Agent 能否从目标与对象形成实际可用的方法，而非只运行给定步骤？ | 在未提供目标 Recipe 的任务上，自行查明相关属性、选择观察层、制作必要检查/绑定并执行。保留公开输入、实际工具动作、方法和结果；只给建议、只 build 或只截图不算通过 |
| S2-2 | 形成的方法是否相关且有区分力？ | 方法确定后检查正常对象和作者未知的相关行为变体；关键缺陷在对应主张被拒绝，正常对象不被无依据判坏。独立检查实际行为，保留漏检/误报，不能由自己写的 PASS 或阶段状态自证 |
| S2-3 | Agent 是否会按观察调整，以及在边界不足时正确停止？ | 使用初始解释不成立的情形和无法支持结论的情形，观察合理切换探针或澄清/停止；实际调查记录完整但不冒充产品通过，也不能通过改变 expected 获取绿色结果 |
| S2-4 | 候选策略内容是否值得保留，而不仅让解释更漂亮？ | 在隔离的新会话配对比较通用指导与附加策略正文，底层 CLI/工具能力相同。记录具体决策、有效结果、人工介入及开销，作出保留/修改/删除内容的决定；不要求新增文本必须胜出 |

**阶段出口：** 一条完成方法探索、实际执行及独立挑战的可复现路径，及必要的 guided/调查支持。可以删减没有净贡献的策略文本；不能把核心探索未做成解释为“仅工具接通也算完成”。小样本不是广域能力或收益证明。

## 5. S3：条件化迁移与方法改进

### 目标

从“一次做出了方法”推进到“换会话、换对象条件仍知道何时可用、何时调整、何时不用”。方法复用的重点是有效策略及适用条件，不是复制步骤或继承旧通过。

### 实现范围

- 使用 S2 产生的实际方法/策略，在至少第二个项目或独立消费环境上检验迁移。安排适用、需要调整和不适用的近似条件；不能只改文件路径证明迁移。
- 完成作者/修订工作路径：反馈 → 方法候选 → 明确接受 → 校准 → 冷会话应用。测试或判据改变后，旧资格不自动支持新 digest；防止为一个新样例修坏原有检查。
- 根据真实迁移需要补最小 import、差异更新、资源搬运及选定报告 export。内容可脱离作者会话和原 `.veripaka/runs` 使用，秘密和本机路径不随方法无选择传播。
- frontend/backend/debug-fix 只作导航，不作为数量配额。已有、形成并验证的路径可整理成对应入口；尚未完成的方向不发布“working”占位。

### 晋级验证：四项

| ID | 唯一要回答的问题 | 代表性验证与留下的证据 |
|---|---|---|
| S3-1 | 下一会话能否发现并正确消费上一阶段形成的方法？ | 在真实安装的冷会话中，不重讲方法主体即可查找、理解条件、绑定并实际执行；保留决策、工具调用和本次结果 |
| S3-2 | 条件变化后会迁移、调整或拒绝，而非盲套吗？ | 在第二项目/消费环境检查适用与不适用近邻；需要调整时生成新绑定/方法修订并独立校准，不适用时保留目标缺口，不能继承旧证据或机械套用步骤 |
| S3-3 | 反馈能否带来真实改进，而非放宽标准或过拟合？ | 另一个会话依据反馈复现遗漏，形成明确修订；后续冷会话检出相关新变体，同时保持原正常/故障检查有效，保留接受理由与资格变化 |
| S3-4 | 方法和选定结果能否脱离作者环境使用与复核？ | 显式搬运到没有原运行目录的环境，必要 helper、参考与材料可解析，无本机秘密或旧资格冒充；真实执行与仅查看历史报告分别标明 |

**阶段出口：** 在声明条件下有迁移和改进记录的方法资产及消费路径，不宣称任意领域通用。不新增 marketplace、完整 history UI 或通用 DAG。

## 6. S4：探索 / 复用价值归因与扩展决策

### 目标与两条评估任务线

分别回答：首次面对任务时是否更会测试；积累之后是否减少重复劳动；CLI 相对同样知识文本是否值得保留。不能用已写好 Recipe 的执行成功率代表方法发现能力。

- **探索线：**不给与目标直接对应的完整 Recipe；提供相同的目标事实、工具资料和权限，检验选择观察/判据、形成方法及实际效果。
- **复用线：**知识组拿到同一份冻结的方法内容，面对新的适用/需调整/不适用任务，检验正确复用与维护成本。

### 对照条件

| 组别 | 条件 | 主要用途 |
|---|---|---|
| A | 同一模型 + 原工作方式，无新增通用 Skill 或方法库 | 实际基线 |
| B | 同模型 + 通用自测 Skill | 分离一般提醒/指导的作用 |
| C | 同模型 + B 的共同指导 + 策略/方法文档，不用 Veripaka CLI | 检查知识内容的贡献；探索线不能偷偷加入目标 Recipe |
| D | 同模型 + 与 C 相同的内容 + Veripaka CLI | 检查执行结构的额外贡献与开销 |

C/D 的候选方法、判据、工具资料和底层操作能力保持一致，D 不额外获得目标事实或隐藏答案。独立评估使用各组实际结果，不以只有 D 能产生的 CLI 格式作为共同成功定义。B→C 的差异可能同时含策略与项目方法的贡献，结合两条任务线解释；需要进一步归因时再安排针对性消融，不预设大规模全因子实验。

使用隔离副本和新会话，平衡顺序、状态与缓存；开发/校准材料和留出评估材料分离，方法生成会话不得获知隐藏变体；提示、策略和评分口径冻结，参与任何内容修订的留出结果转为校准材料，不再用于独立验收。保留正常、故障、缺环境、失败、超时与未完成样本。关键结果由独立行为检查、可复核对象事实或盲审决定，不用 Agent 自评当真值。

先用 pilot 检查测量可行性和估计差异；量化收益主张须另用独立任务集和足够样本。在比较前登记质量容忍、必要人工澄清与代做步骤的区别、人工复核口径、可观察成本和最低有用改善要求，不见到结果后再定成功线。

### 晋级/结束验证：四项

| ID | 唯一要回答的问题 | 代表性验证与留下的证据 |
|---|---|---|
| S4-1 | 探索与复用各自的质量如何，是否独立判定？ | 分开报告方法相关性、缺陷检出、false pass、误报和合理保留未知；不把协议走完、建议流畅或所有任务都拒绝回答计作有效测试 |
| S4-2 | 用户是否少做了方法设计和重复解释？ | 按任务记录首次设计、补充说明、代做步骤、复核和迁移维护劳动；正常澄清与把整项工作退给用户分开计数 |
| S4-3 | 首次投入与后续复用的总成本是否合算？ | 计入资料整理、方法探索/校准、逐次执行、修订和人工复核；未知项标 unknown，在实际复用次数下评估，不只报推理 token |
| S4-4 | 哪部分贡献支持什么取舍？ | 对照 A/B/C/D 的质量、劳动与成本，明确继续、先修方法选择、保留文本但缩减 CLI、收窄适用域或暂停；说明证据和局限 |

这里的完成是得到可复核的取舍依据，不要求 D 获胜。协议性假通过应修复，不能用平均成本更低为其辩护；数据不足时不发布普适收益承诺。

## 7. 执行约定、依赖与停止规则

### 先设计复审，再由父 Agent 单线实施

本轮先完成设计与自我反思，再交独立 reviewer 只读复审。明确放行后，由父 Agent 单线推进实现，不委派并发 writer；若有阻断项，先修设计并复审。实现按上述 S2 纵向顺序推进，不把整份 S2—S4 计划误报为已经启动或完成。

每个变更先用相关失败用例驱动，再运行原生回归；到真实消费路径时才以安装后的产品做 E2E。首次外部工具接入要核验版本、公开接口和实际能力；无法观察所需信息时保留 blocker，不用另一种无关绿色检查替代。尤其要实测指定模型与工具是否能消费图像：模型不能直接读图时，只有真正支持相应主张的图像检查器才能替代判断路径，不能把 DOM 成功当作图像验证；两者都不足则视觉任务阻塞。

### 实现 E2E 模型与重试

依用户本轮指定，实现 E2E 只使用 `Mapleluv-ChatCompletions/deepseek-flash:max`，沿用 `--no-extensions --no-session`，必要时显式隔离安装后的 Skill。不切换模型；凭据仍留在用户 provider 配置中。已有 S1 材料中的 `:high` 是历史事实，不改写为 `:max`。

访问/上游传输问题要充分重试并保留每次错误、时间与实际模型记录，必要时退避；持续无法访问则报告基础设施阻塞。若调用已经产生工具副作用，先确认清理/隔离再继续。功能失败、质量不足或工具不可用不伪装成网络故障；不得重跑到绿并丢弃先前样本。正式比较前固定重试政策，各组一致。

### 失败指向下一步，而非扩建平台

| 观察到的问题 | 下一动作 |
|---|---|
| 只有文字建议，没有可执行方法 | 回到任务与观察/干预设计，不加检索基础设施 |
| 普通指导已足够，新策略文本只增加开销 | 删除或压缩内容，承认增量不足 |
| 迁移频繁误用 | 收窄条件、增加不适用反例或保留领域方法，不扩大通用性宣传 |
| 方法有效但找不到 | 依据真实查询记录改检索/入口，再考虑语义索引 |
| 缺采集/隔离能力 | 修任务必需的最小适配或记录阻塞，不放宽来源和安全约束 |
| 文本有用而 CLI 无净贡献 | 缩减执行结构，保留有用内容和必要边界 |
